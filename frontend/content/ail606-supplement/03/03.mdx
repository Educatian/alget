# Image Generation for Instruction

![Image Generation for Instruction textbook visual](/course-art/deep-exemplars/ail606-supplement/03-03-image-generation-for-instruction.png)

## Why This Section Matters

Generative image tools have collapsed the cost of producing a striking picture to near zero, which is exactly why they are dangerous in instruction. A text-to-image model optimizes for plausibility and aesthetic appeal, not for instructional accuracy, and it has no model of your learning objective. It will happily render a "lever" that violates physics, a "cell" with the wrong organelles, or a richly detailed scene whose detail is precisely the seductive distraction that depresses learning. The designer's job shifts from making images to commissioning, screening, and verifying them.

This section treats image generation as a specification-and-verification problem. The instructional value of an image is set before the prompt, by naming the function the image must perform (what relationship or distinction the learner must be able to read from it), and confirmed after generation by checking the render against the content, not against your taste. A beautiful image that is decorative, inaccurate, or detail-laden is not an asset; it is a liability the tool produced cheaply.

## Opening Case

A designer needs an image of a plant cell for a middle-school biology frame. The first generation is gorgeous: lush green, dramatic lighting, a cell bursting with detail. It is also wrong. The model has rendered animal-cell features inside a structure labeled "plant cell," added several organelles the lesson never covers, and buried the cell wall, the one structure the frame is supposed to teach, behind decorative texture. Accepted on looks, this image would teach a misconception.

The picture's appeal is the trap. Because it looks authoritative and was free to make, the designer is tempted to ship it. This section asks for the opposite reflex: a generated image is a draft to be interrogated against the content and the objective before it earns a place on the frame.

## Core Concept

An instructional image has a **representational function**: it makes a relationship, structure, or distinction visible so the learner can read it directly rather than inferring it from text. Specifying that function is step one, and it constrains everything downstream. "Show a lever" is not a function; "show that moving the fulcrum toward the load increases mechanical advantage" is, because it tells you the image must contrast two effort-arm lengths, which a single pretty lever cannot do.

Two principles govern what to keep out. Mayer's **coherence principle** says removing interesting-but-extraneous material improves learning; the corollary is the **seductive-detail effect**, where vivid, engaging elements (the photorealistic studio, the dramatic light) actively pull attention from the to-be-learned relationship. Generative tools manufacture seductive detail by default, so coherence is usually a subtraction task: re-prompt toward a clean diagram, not a rich scene.

Two more checks decide whether the image is fit to ship:

- **Accuracy verification.** The model has no commitment to truth, so every label, count, proportion, and relationship must be checked against the authoritative content source. Treat the first render as an unverified claim.
- **UDL and access.** An image that carries meaning by color alone, or that has no functional alt text, excludes learners; representational images create an accessibility obligation handled in 03.05.

Cognitive load theory ties these together: extraneous visual detail and inaccurate elements both spend working memory the learner needs for the actual relationship, so a "better-looking" image can be a worse instructional one.

## Worked Example: Choosing and Verifying a Generated Instructional Image

The lesson teaches how a lever multiplies force. Below is the before/after of one image decision.

**Before (first generated image, accepted on looks):**

> Prompt: photorealistic woodworking studio, dramatic light, a crowbar resting on a workbench among many tools. The render is striking. Caption: looks great, students will love it.

Problems: the scene is decorative. The fulcrum, load, and effort are not distinguishable, the crowbar sits among competing detail (seductive detail), and nothing was verified against the lever model.

**After (re-prompted toward the learning function, then verified):**

> Learning function named first: the learner must see that moving the fulcrum closer to the load increases mechanical advantage. Prompt: clean labeled line diagram, one lever, fulcrum-load-effort marked, two effort-arm lengths shown side by side. Caption: shows the relationship, then I checked it.

Annotated decision trail:

1. Started from the learning function (fulcrum position changes advantage), not from a style prompt.
2. Cut decorative and seductive detail: removed the studio scene so attention stays on the lever geometry.
3. Verified accuracy: confirmed the diagram labels effort, load, and fulcrum correctly and that the longer effort arm is drawn on the higher-advantage side. The first generated draft had swapped load and effort labels; that was corrected.
4. Rejected suggestion: the AI proposed adding a person pushing the lever for relatability. Rejected, because the figure added detail without clarifying the distance relationship the lesson depends on.

The improvement is not a prettier image. It is an image chosen for its instructional function and verified against the content.

## Decision Rule

Commission, then verify, in that order. Before prompting, write the image's function in one sentence: "the learner must be able to read [relationship/structure/distinction] from this image." The prompt then specifies that function (clean diagram, labeled parts, two cases shown side by side) rather than a mood.

After generation, run the three-gate screen and reject at the first failure:

1. **Function gate:** Can a learner read the named relationship from this image without reading the caption? If the relationship is not visible, re-prompt; do not patch it with text.
2. **Coherence gate:** What in this render is decorative or seductive (scenery, lighting, extra figures, ornamental detail)? Strip it; if the model will not strip it, switch to a diagram style.
3. **Accuracy gate:** Check every label, count, and proportion against the source. Models routinely swap labels (load/effort), miscount items, and invent parts. One verified error means the image is not shippable until corrected.

Polish is the last gate, not the first; a striking image that fails any earlier gate is rejected regardless of how good it looks.

## Common Misreadings

The first misreading is "photorealism equals quality." For most instructional functions a clean line diagram outperforms a photo, because the photo carries surface detail (texture, background, lighting) that competes with the relationship being taught. The second misreading is trusting the model on facts: because the render looks confident and professional, designers skip verification, and ship images with swapped labels or impossible structures. The model is fluent, not accurate; fluency is exactly what makes its errors hard to catch.

## Textbook Walkthrough

Walk a real commission. A frame must teach that series circuits share one current path while parallel circuits split it. Function sentence: "the learner must be able to read, from a side-by-side image, that current has one path in series and multiple paths in parallel." First prompt yields a photorealistic breadboard with tangled jumper wires, beautiful and useless, because the single-versus-multiple-path distinction is invisible under the clutter (function gate fails). Re-prompt: "schematic, two simple circuits side by side, left labeled series with one loop, right labeled parallel with two branches, no breadboard, no photoreal detail." The second render shows the contrast cleanly (function gate passes, coherence gate passes). Accuracy gate: confirm the parallel branches actually rejoin and the battery polarity is consistent; the first draft had drawn the branches without a shared node, which would teach a wrong model, so that is corrected before shipping.

The walkthrough shows the order doing the work: naming the function ruled out the photoreal style, coherence ruled out the clutter, and verification caught a structural error the eye glides past.

## What Strong Reading Looks Like

Read every generated image as an unverified claim and audit it. For each image in the chapter, name the function it is supposed to perform, then list what in the render is extraneous to that function and what you would check against a source. A strong reader does not ask "is this image good?" but "what relationship must a learner read here, is it readable, and is it true?" Train the habit of finding the one decorative element that, if removed, would lose nothing instructional, and the one factual claim the picture makes that you would not yet trust.

A strong reader of instructional image generation can, for any image, state its representational function, point to the seductive detail to cut, and name the specific fact to verify.

## Stronger Artifact Standard

The artifact reaches the stronger standard when the trace shows the commission-and-verification cycle, not just a final picture. It records the function sentence written before prompting, at least one rejected generation with the gate it failed (decorative, inaccurate, or wrong style), and an explicit verification note ("checked fulcrum, load, effort labels against the physics text; corrected a swapped pair"). Where an AI suggestion added relatable detail (a person, a setting), the trace records rejecting it for failing the coherence gate.

A strong closing note reads: "I re-prompted the lever image away from a photoreal workshop toward a labeled diagram that contrasts two effort-arm lengths, because the original could not show the distance relationship the lesson depends on. I verified the effort, load, and fulcrum labels against the source and corrected a swapped pair. I rejected the tool's suggestion to add a person pushing the lever because it added detail without clarifying the relationship."

## Transfer Case

Move from a generated diagram to a generated photo for a soft-skills scenario, say a customer-service role-play image. The accuracy gate changes character: there is no physics to check, but there is representation to check, because the model defaults to stereotyped depictions of role, gender, age, and ethnicity that can misteach or alienate. The coherence and function gates still apply (does the image show the interpersonal dynamic the scenario teaches, free of distracting detail?), but verification now means auditing for bias and representativeness against the actual learner population. The transfer test is whether you can keep the commission-then-verify discipline when "accuracy" means social accuracy rather than factual accuracy. If your verification step only knows how to catch a swapped label, it will pass an image that teaches a stereotype.
