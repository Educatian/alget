Alt text is the most misunderstood accessibility control in instructional design. Many designers treat it as a description of the picture, so they write what the image looks like ("a colorful bar chart"). But alt text exists to deliver the image's instructional function to a learner who cannot see it, which is almost never the same as describing its appearance. The right question is not "what does this image show?" but "what is a learner supposed to learn from this image, and how do I carry that meaning in words?"

This section treats accessibility as a design obligation that is decided when you choose the image, not bolted on at the end. It covers the three decisions that actually determine whether an image is accessible: classifying the image (decorative versus meaningful, which sets whether alt is empty or content-bearing), writing functional alt that carries the learning point concisely, and ensuring no meaning rides on color alone. Done well, accessibility is invisible and improves the design for everyone; done as an afterthought, it produces alt text that satisfies a checker and teaches nothing.

## Learning Targets

- Classify an instructional image as decorative, informative, or functional and assign the correct alt treatment.
- Write functional alt text that carries an image's instructional meaning, and move dense data to an adjacent table or long description.
- Audit a visual for color-only coding and add a redundant cue per WCAG 2.2 SC 1.4.1.
- Apply the cover test and reject over-long AI-generated alt text with reasons.

## Opening Case

A frame presents a bar chart comparing test scores across three teaching methods, with alt text that reads "a colorful bar chart with blue, green, and orange bars." An automated accessibility checker passes it: the alt attribute is present and non-empty. Yet a screen-reader user learns nothing the chart was meant to teach, no ranking, no margin, no result, only that some colored bars exist. The checker measured presence; it could not measure function.

Worse, the bars are distinguished by color alone, so a color-blind learner who can see the chart also cannot tell the series apart. The frame is "accessible" by automated audit and inaccessible in practice. This section asks you to expose that gap: passing a checker is not the goal, delivering the instructional meaning through a non-visual path is.

## Core Concept

Accessible images turn on three distinct decisions, each with its own rule.

First, **classification**. An image is either decorative (it adds no information the surrounding text lacks, for example a header rule or a stock photo of a campus) or meaningful (it carries content a learner must get). Decorative images take empty alt (`alt=""`) so a screen reader skips them; announcing "decorative divider line" is noise that wastes a non-visual learner's attention. Meaningful images take content-bearing alt. Misclassifying in either direction harms: empty alt on a meaningful chart hides the content, verbose alt on decoration buries it.

Second, **function over appearance**. For a meaningful image, the alt must convey what the learner should take from it, the ranking, the relationship, the value, not the colors or layout. Compare "blue, green, orange bars" (appearance) with "inquiry scored highest at 82, then lecture at 74, then lab at 70" (function). Keep it brief; alt is read linearly with no skimming, so a complex chart's full data belongs in an adjacent table or a long description, with the alt giving the headline.

Third, **do not encode meaning in color alone** (WCAG 2.2 success criterion 1.4.1, Use of Color; the alt obligation behind the first two decisions is SC 1.1.1, Non-text Content). If series are told apart only by hue, color-blind learners lose the distinction even with full sight; add a redundant cue, direct labels, patterns, or values on the bars. The operative conformance target as of 2026 is WCAG 2.2 AA, a W3C Recommendation since October 2023; WCAG 3.0 remains an early, exploratory W3C Working Draft that is still years from becoming a standard, so design and audit against 2.2.

These map onto the course anchors. UDL learner variability is the driver: design for the range of sensory and perceptual access, not the median learner (UDL Guidelines 3.0 frames sensory and perceptual access as ordinary learner variability to design for, not a special accommodation). Mayer's coherence principle keeps alt brief, because over-long alt is extraneous load delivered through the ear. And accessibility is a multimedia decision, not a compliance afterthought, so it belongs at image-selection time, beside the function and coherence decisions of 03.03.

## Worked Example: Rewriting Alt Text for a Bar Chart

A frame presents a bar chart comparing test scores across three teaching methods. Below is the before/after of its accessibility treatment.

**Before (appearance, not function):**

> alt = "A colorful bar chart with blue, green, and orange bars on a white background." The series are distinguished by color only. No transcript.

Problems: the alt text describes pixels, not the comparison the chart teaches. A screen-reader user learns nothing about the result, and a color-blind learner cannot tell the series apart.

**After (function carried in words, color not load-bearing):**

> alt = "Bar chart: average score was highest for inquiry (82), then lecture (74), then lab (70); inquiry led by 8 points." Each bar is also labeled with its method name and value, so color is decorative, not the only cue. A short data table sits beside the chart.

Annotated decision trail:

1. Rewrote alt to convey the instructional function (the ranking and the 8-point gap), not the colors.
2. Removed color-only coding: added on-bar labels so the distinction survives color blindness and grayscale.
3. Classified the image as meaningful, so it earns content-bearing alt, unlike the page's decorative header rule, which takes empty alt.
4. Handled complexity: kept the alt brief and added a nearby data table for learners who need every value.
5. Rejected suggestion: the AI proposed a 200-word alt attribute listing all values. Rejected, because alt should stay brief; the full data belongs in the adjacent table.

The improvement is access carried by structure, brief functional alt plus a readable equivalent, not a longer color description.

## Decision Rule

Run every image through the accessibility sequence in order:

1. **Classify:** Is this image decorative or meaningful? Decorative gets `alt=""`. Meaningful gets content-bearing alt. If you are unsure, ask whether the surrounding text already conveys what the image conveys; if it does, the image is decorative.
2. **Write to function, briefly:** For a meaningful image, state what the learner should take from it in one tight sentence. If the image is data-dense, give the headline in alt and put the full values in an adjacent table or long description.
3. **Audit color:** Is any distinction carried by color alone? If yes, add a non-color cue (labels, values, patterns) so the meaning survives color blindness and grayscale, per WCAG 2.2 SC 1.4.1.

A defensible image decision can answer all three: how it was classified, what function its alt carries, and how it avoids color-only coding. The right test is the cover test: hide the image and read only the alt, can a learner still get the point?

## Common Misreadings

The first misreading is "more alt text is better alt text." Long, exhaustive alt is itself a barrier, because screen-reader output is linear and unskimmable, so a 200-word alt forces the learner to listen through everything to find the point; brevity plus an adjacent data table serves them far better. The second misreading is "passing the checker means it is accessible." Automated tools verify that alt exists and flag a few color-contrast ratios, but they cannot tell whether the alt carries the instructional function or whether a distinction depends on color, the two failures that matter most. Human judgment, not the checker, is the standard.

## Textbook Walkthrough

Walk a real frame with mixed images. The frame has a decorative banner photo of a lab, a meaningful line graph of reaction rate versus temperature, and a small "click here" arrow icon. Classify each: the banner is decorative (`alt=""`), the graph is meaningful, the arrow is functional UI whose alt should name its action ("expand the data table"), not its shape. Write the graph's alt to function: "reaction rate rises slowly up to 40C, then climbs sharply, doubling between 40 and 60C," with the precise values placed in a table beside it. Audit color: the graph plotted two reactions in red and green only, so add direct end-of-line labels so the two curves are distinguishable without color.

Apply the cover test: hide the graph and read the alt plus the table, a non-visual learner gets the trend and the numbers; a color-blind learner reading the visible graph gets the labels. The walkthrough shows the three decisions are separable: classification fixed the banner, function fixed the alt, and the color audit fixed a defect the alt alone would have missed.

## What Strong Reading Looks Like

Read every image in the chapter twice, once for classification and once for the cover test. For each, decide decorative or meaningful and predict the alt it should carry; then imagine the image hidden and ask whether the alt alone would teach the point. A strong reader catches the two silent failures: alt that describes appearance instead of function, and a distinction that quietly depends on color. Keep a note of which images would need an adjacent table because their data is too dense for alt to carry.

A strong reader of accessibility can, for any image, state its classification, the function its alt must deliver, where the full data lives if alt cannot hold it, and whether any meaning rides on color.

## Stronger Artifact Standard

The artifact reaches the stronger standard when the trace shows the classify-function-color sequence applied per image, including at least one image correctly marked decorative with empty alt and one meaningful image whose alt was rewritten from appearance to function. It records the cover test being run, and where data was dense, names the adjacent table or long description. Where an AI tool generated an exhaustive paragraph-length alt, the trace records trimming it to the headline and moving detail to a table.

A strong closing note reads: "I reclassified the lab banner as decorative and gave it empty alt so screen readers skip it, and I rewrote the chart alt from a color description to the ranking and the eight-point gap it teaches. I added on-bar value labels so the comparison survives color blindness, and put the full values in a table beside the chart. I rejected the tool's 200-word alt because linear audio makes exhaustive alt a barrier, not a help."

## Transfer Case

Move from a static image to a data dashboard the learner can filter and re-sort interactively. Alt text alone cannot describe a display that changes on interaction, so the obligation transfers but the mechanism does not: accessibility now means a keyboard-operable interface, programmatic labels that update as the data changes, and a downloadable data table as the reliable equivalent. The transfer test is whether you can carry the function-not-appearance principle into a dynamic artifact where the "image" is never fixed. If your accessibility skill only knows how to write one alt string for one static picture, it will not survive the move to interactive media; the durable skill is guaranteeing a non-visual path to the same meaning, whatever form the visual takes.
