# Problem Statement and Learner Profile

![Problem Statement and Learner Profile textbook visual](/course-art/deep-exemplars/ail606-supplement/04-01-problem-statement-and-learner-profile.png)

## Why This Section Matters

Every instructional design project begins with two claims that the rest of the design has to honor: a claim about the gap (the problem statement) and a claim about who has the gap (the learner profile). When these two claims are vague, every downstream decision becomes arbitrary, because there is nothing concrete to design against. AIL 606 treats the problem statement and learner profile as the load-bearing foundation of the storyboard: each frame you later draft should be defensible by pointing back to a specific performance gap and a specific learner attribute.

This section teaches you to write a problem statement that locates a performance gap (not a feeling) and a learner profile that drives design (not flatters the audience). You should leave able to test whether a profile attribute actually constrains a frame decision, and able to explain why "make it more engaging" is not yet a designable goal.

## Learning Targets

- Write a problem statement that names a located performance gap, its conditions, and a measurable target.
- Build a learner profile in which every attribute changes at least one storyboard decision.
- Separate design-driving attributes (prior knowledge, context of use, language) from flattering adjectives (motivated, smart).
- Document how a revised problem statement changes which evidence would count as success.

## Opening Case

A district hires you to fix a safety onboarding module because "completion rates are low." You could accept that framing and start redesigning screens. Instead, you pull the analytics and find that 70 percent of new hires reach screen 2 and then abandon, almost all within the first three days of hire. Screen 2 opens with nine unexplained acronyms. The "low completion" symptom is now a located gap: novices with low domain vocabulary hit a recall wall before any practice. The redesign target writes itself, and it has nothing to do with engagement.

The lesson of this case is that the presenting complaint and the actual problem are rarely the same sentence. The problem statement is where you do the work of converting a complaint into something a storyboard can be built against.

## Core Concept

A problem statement is the gap between current and desired performance, stated with enough specificity that you could later test whether it closed. A useful problem statement carries four parts: the actor (who is failing to perform), the located gap (where in the task or screen the performance breaks down), the conditions (the context and constraints under which it happens), and a measurable target (what "fixed" would look like in numbers or observable behavior). Strip any of these and the statement degrades into a slogan.

The learner profile is the discipline of describing your audience only in terms that change a design decision. The relevant categories come straight from instructional analysis: prior knowledge (what schemas the learner already holds), context of use (device, time pressure, environment), and learner variability (language, accessibility needs, motivation barriers). The test for any profile line is the design-consequence test: if changing the attribute would change no frame, no media choice, and no sequence, it does not belong in the profile.

| Weak attribute (no design consequence) | Design-driving attribute | What it constrains |
| --- | --- | --- |
| "Motivated and eager to learn" | "Completes the module in 5-minute bursts between shifts" | Resumable checkpoints; short segments |
| "Tech-savvy adults" | "First exposure to compliance vocabulary" | Glossary tooltip before the acronym list |
| "Diverse learners" | "Roughly 1 in 5 use a screen reader" | Alt text and reading-order pass on every frame |

The deeper principle is that the problem statement and profile must be mutually consistent. A target of "under 90 seconds to first correct action" is only meaningful given the profile that says the user is a novice working on a shared tablet between shifts. The number and the person define each other.

## Worked Example

Work through one annotated before/after revision of a problem statement and learner profile, the way you would defend it in a design review.

**Before (draft packet, cover panel):**

> Problem: Learners are not engaging with the safety onboarding module. Audience: adult learners who are motivated and tech-savvy. Goal: make the module more engaging.

**Annotations a reviewer would leave:**

1. "Not engaging" is a symptom, not a located gap. Where exactly does the learner stall, and what creates the demand there?
2. "Motivated and tech-savvy" are praise adjectives. Neither one would change a single storyboard frame, so they do not belong in a design-driving profile.
3. "Make it more engaging" is a solution dressed as a goal. There is nothing here a later revision could be tested against.

**After (revised cover panel):**

> Problem: New hires in days 0 to 30, with low domain vocabulary, abandon the onboarding module at screen 2, where an unexplained 9-acronym list imposes a high recall load before any practice.
> Learner profile: low prior domain knowledge; completing the module on a shared shop-floor tablet between shifts (short, interrupted sessions); first exposure to the compliance vocabulary.
> Goal: reduce time-to-first-correct-action for novices from 4 minutes to under 90 seconds.

**Why the after version is stronger:** each profile attribute now constrains a frame decision (the interrupted-session attribute justifies resumable checkpoints; the low-vocabulary attribute justifies a glossary tooltip before the acronym list), the gap is located at screen 2 with a named source of demand, and the goal is measurable, so the next storyboard revision can be evaluated against it. The change is a better evidence trace, not longer wording.

## Decision Rule

Treat each profile attribute as a hypothesis about design, then keep only the ones that pay for themselves in a decision. Apply three tests before the storyboard frame sequence leaves the cover panel:

1. **Located-gap check:** Does the problem statement name where performance breaks, under what conditions, for whom?
2. **Design-consequence check:** Does every profile line change at least one frame, media choice, or sequence? Delete the rest.
3. **Testability check:** Is the target stated so that you could later measure whether it closed?

If you cannot answer all three, the cover panel is written but not yet designable.

## Common Misreadings

The most common error is writing the learner profile as a compliment to the audience. Adjectives like "motivated" and "intelligent" feel respectful but constrain nothing; they are decoration, not analysis. The second error is treating the presenting complaint as the problem statement, which freezes the design around a symptom and quietly skips the analysis that would have relocated the gap.

A profile is design analysis, not audience flattery, and a problem statement is a located gap, not a restated complaint.

## Textbook Walkthrough

Begin with the complaint exactly as the client gave it, then refuse to design against it until you have located the gap. Pull whatever evidence exists (analytics, observation, a brief task analysis) and find the screen, step, or moment where performance actually breaks. Convert that into the four-part statement: actor, located gap, conditions, measurable target.

Now build the profile by reverse-engineering it from the gap. Ask what about these learners makes this particular break happen here. Low vocabulary explains the acronym wall; interrupted sessions explain abandonment mid-module. Each attribute you add should answer a "why does the gap occur" question, which guarantees it has a design consequence.

Finally, stress-test consistency. Read the target number aloud and ask whether it makes sense for the person in the profile. If "under 90 seconds" assumes an expert but the profile says novice, one of the two is wrong. The cover panel is finished when the gap, the person, and the number tell one coherent story.

## What Strong Reading Looks Like

As you read, keep a two-column note: **claim** on the left, **evidence** on the right. The claim is the design decision you think a profile attribute is forcing; the evidence is the specific frame, sequence, or media choice it constrains. By the end of AIL 606 04.01, your notes should let a reviewer reconstruct why each profile line earns its place.

A strong reader of a problem statement and learner profile can answer four questions:

1. What located gap does this statement name, and how would you measure it?
2. Which single profile attribute is doing the most design work here?
3. Which profile line could be deleted with no effect on the storyboard?
4. How would the target change if the device or prior knowledge changed?

## Stronger Artifact Standard

The artifact is strong when a reviewer can trace a straight line from a profile attribute to a frame decision to the measurable target. Treat polish as the last layer; the foundation is the located gap, the design-driving profile, and the testable goal. Where an attribute does not yet connect to a frame, mark it with the annotation tools and ask BigAL for a targeted comparison between a flattering profile and a design-driving one rather than a generic explanation.

A useful final paragraph for the artifact would sound like this: "I rewrote the problem statement to locate the gap at screen 2 and set a 90-second target, and I kept only the three profile attributes that each force a specific frame change. I dropped 'motivated and tech-savvy' because it changed nothing in the storyboard."

## Transfer Case

Move the same module from new-hire onboarding to annual refresher training for experienced staff. The presenting complaint ("low completion") may look identical, but the profile inverts: prior knowledge is now high, so the acronym wall is no longer the gap, and a 90-second novice target is meaningless. The located gap might shift to "experienced staff skim and miss the one policy change this year." Transfer here means re-running the analysis, not copying the cover panel; if you understand the section, the new profile produces a different problem statement.
