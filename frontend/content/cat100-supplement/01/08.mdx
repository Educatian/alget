# Module 1 Readiness Studio

![Module 1 Readiness Studio textbook visual](/course-art/deep-exemplars/cat100-supplement/01-08-module-1-readiness-studio.png)

## Why This Section Matters

This studio is where the separate skills of Module 1 stop being separate. A real artifact, like a profile slide or a short project page, demands all of them at once: the claims must be truthful (1.1), any AI help must be disclosed (1.2 to 1.4), the design must be accessible (1.6), and the accounts behind it must be safe (1.5). The readiness check is an honest self-audit that asks, for one shared artifact, which skills you can actually demonstrate and which still have a gap.

The work product is a readiness map: each Module 1 skill checked against the same artifact, marked pass or gap, with the gaps flagged for targeted practice. The point of the studio is not to declare yourself finished; it is to find the one or two things that are not yet ready before they cost you on a graded assignment.

## Learning Targets

- Audit a single artifact against all four Module 1 skills at once.
- Mark each skill honestly as pass or gap based on what the artifact actually shows.
- Resist the urge to check every box; flag real gaps instead of hiding them.
- Convert each gap into a specific, targeted practice step.

## Opening Case

Rosa is about to submit her class profile slide and move to Module 2. She runs the readiness check across all four skills. Her resume bullet is truthful, her AI-use note is present, and her slide has alt text and a real heading. But when she checks privacy, she realizes two-factor authentication is not yet on for her school email. Three skills pass; one has a real gap.

The tempting move is to mark privacy "good enough" and submit. The studio's lesson is the opposite: flag the gap, enable 2FA, and re-check that one row. An honest map with one flagged gap is more useful than a clean map that hides a real weakness.

## Core Concept

A readiness check is integration, not repetition. The earlier sections taught each skill in isolation; the studio tests whether they hold together on one artifact under one set of eyes. The instrument is a single table that lists each skill, the exact thing you inspect on the artifact, and an honest status.

| Skill (from this module) | What you inspect | Honest status |
|--------------------------|------------------|---------------|
| Truthful evidence (1.1) | Does each claim survive a reference check? | Pass / Gap |
| AI disclosure (1.2 to 1.4) | Is AI use named, with a rejection logged? | Pass / Gap |
| Accessibility (1.6) | Alt text, headings, color, contrast | Pass / Gap |
| Privacy (1.5) | Unique password, 2FA, no exposed data | Pass / Gap |

Two ideas make the check work. First, you inspect the actual artifact, not your memory of it: open the slide, read the alt text, look at the disclosure, check the 2FA setting. Memory inflates readiness; inspection corrects it. Second, a flagged gap is a feature, not a failure. The whole value of a self-audit is finding the gap while you still have time to fix it; a check that always returns "all pass" is performing readiness rather than measuring it.

## Worked Example

A first pass at a readiness check often hides the real state behind optimism:

> Everything looks ready.

That sentence is too thin because it names no skill and reflects no inspection. It is a feeling, not an audit. A strong readiness map runs each skill against the artifact and reports the true status, including any gap.

### Worked Example: running the Module 1 readiness check, step by step

Test all four module skills against one shared profile slide before moving to Module 2.

| Skill (from this module) | What you check on the slide | Status |
|--------------------------|-----------------------------|--------|
| Truthful evidence (1.1) | Bullet reads "Co-led a 4-person team" and is accurate | Pass |
| AI disclosure (1.2 to 1.4) | A note lists the AI brainstorm and the rejected thesis rewrite | Pass |
| Accessibility (1.6) | The slide image has alt text and uses a real heading style | Pass |
| Privacy (1.5) | Two-factor authentication is on; no student ID shown | Gap: 2FA not yet enabled |

1. **Run each row honestly**, opening the artifact rather than assuming.
2. **Flag the gap, do not hide it.** Privacy is not ready: 2FA is off.
3. **Request targeted practice** on enabling two-factor authentication, then re-check that one row.

Result: three skills confirmed against real evidence and one gap flagged for practice. That honest readiness map is more useful than checking every box at once.

## Decision Rule

For each skill, mark pass only if you just inspected the artifact and the evidence is actually there; otherwise mark gap and write the specific fix. Do not average the skills into a single "ready" feeling, because one real gap (an exposed account, a false claim) can undermine the whole artifact regardless of how strong the other rows are. The honest call on the weakest row is more important than the count of passing rows.

1. **Inspection check:** Did you open the artifact for each row, or rely on memory?
2. **Gap check:** Is every gap flagged with a specific fix rather than smoothed over?
3. **Re-check loop:** After fixing a gap, did you re-run that one row to confirm the fix?

## Common Misreadings

The most common error is the all-pass reflex: marking every row "good" because admitting a gap feels like admitting failure. But a readiness check that never finds a gap is useless; its entire purpose is to surface the weak row before a grader does. A map with one honest gap shows more skill than a flawless map that is not true.

A second misreading is fixing a gap and forgetting to re-check it. If privacy was a gap and you enable 2FA, the row is not "pass" until you confirm 2FA is actually on. The loop is inspect, fix, re-inspect; skipping the final inspection leaves you believing a problem is solved when it may not be.

## Textbook Walkthrough

Imagine a peer-review pairing in the studio: you audit a classmate's project page and they audit yours, each using the four-row table. You open their page and check the resume line against plausibility, look for an AI-use note, test the images for alt text and the text for contrast, and ask whether any private data is exposed. You find the page passes three rows but shows a phone number in a contact image with no indication it was meant to be public, so you flag a privacy gap. They find that one of your headings is just bold text, so they flag an accessibility gap.

The walkthrough shows why the studio uses a shared, inspectable table: it makes the audit transferable between people. Because the rows name exactly what to inspect, a classmate can run the same check you would, and the gaps they flag are specific enough to fix. Readiness becomes a shared, evidence-based judgment rather than each person's private sense that their work is "probably fine."

## What Strong Reading Looks Like

When you read a readiness map, look for whether the statuses came from inspection and whether the gaps are honest. A map that is all "pass" with no inspection notes is suspect; a map that flags a gap and names the fix shows a learner who is actually auditing rather than performing. The presence of a well-handled gap is a sign of strength, not weakness.

A strong reader of a readiness map can answer four questions:

1. Was each row checked against the actual artifact?
2. Is every status honest, including the gaps?
3. Does each gap have a specific, targeted fix?
4. Were fixed gaps re-checked before being marked pass?

## Stronger Artifact Standard

Your readiness map is strong when each row's status is backed by an inspection a reviewer could repeat, and every gap carries a concrete next step. The earlier layers are the per-skill checks from sections 1.1 through 1.7; the studio's added layer is honest integration. If you are unsure whether a row passes, mark it a gap and ask BigAL to help you inspect that specific element rather than asking it to declare you ready.

A useful note would read: "Across my profile slide, truthful evidence, AI disclosure, and accessibility pass on inspection. Privacy is a gap because 2FA is off; my next step is to enable app-based 2FA on my school email and re-check that row before submitting."

## Transfer Case

Carry the readiness-check habit into any multi-requirement deliverable later in college or work: a lab report, a portfolio submission, a job application packet. The structure transfers directly. List the requirements as rows, name the exact thing to inspect for each, open the actual artifact, mark pass or gap honestly, and convert gaps into specific fixes before you submit. The constraint changes (the requirements come from a rubric or a job posting rather than this module), but the method does not: integration through honest, repeatable inspection. A student who has practiced flagging their own gaps here will, later, catch the missing requirement in a real submission instead of discovering it in the grade.
