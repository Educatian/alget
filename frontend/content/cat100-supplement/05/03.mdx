# Image Generation for Explaining Ideas

![Image Generation for Explaining Ideas textbook visual](/course-art/deep-exemplars/cat100-supplement/05-03-image-generation-for-explaining-ideas.png)

## Why This Section Matters

AI image generators make it trivial to produce a picture, which is exactly why they are dangerous on a slide. A generated image looks authoritative, but the model does not know your process; it predicts plausible-looking pixels. If you ask for a diagram of your data pipeline, the tool may confidently produce one with the stages in the wrong order, and a viewer will trust the picture precisely because it looks finished.

This section teaches the difference between an image that explains and an image that decorates, and the verification habit that keeps a generated diagram honest. The artifact is an AI critique log recording which generated outputs you accepted, modified, and rejected, so a reviewer can see that you checked the picture against reality rather than pasting whatever the model produced.

## Opening Case

A student needs a slide that explains how their app moves data: collect, then clean, then analyze. They type "make a cool tech graphic for data" into an image tool and get a glowing brain wired to floating numbers. It looks impressive and explains nothing; a viewer learns the slide is "about data" and stops there. The student who instead prompts for three labeled boxes in a specific order, then checks each label against the real steps, gets a picture that does the teaching the bullets would otherwise have to do.

## Core Concept

An image on a slide is either **explanatory** or **decorative**, and you should know which one you are placing. An explanatory image carries information the audience needs and that text alone would carry less efficiently: a process flow, a relationship, a before-and-after, a labeled structure. A decorative image carries mood but no information; remove it and the slide loses nothing it needed. Decoration is not banned, but it must never crowd out or impersonate explanation.

Generated images add a second axis: correctness. The model produces something that *looks* like an explanation without any guarantee that the content is true. So an explanatory generated image must pass two tests, in order:

- **Specification.** Did you tell the model the exact parts, labels, and relationships, rather than asking for a vibe? "Three labeled boxes, Collect then Clean then Analyze, arrows showing flow" is a specification; "a cool data graphic" is a vibe.
- **Verification.** Does every label, arrow, count, and order in the output match your real process? Generators routinely transpose steps, misspell labels, and invent extra elements.

The data-ink anchor decides whether the image earns its place (does it carry meaning the slide needs); the verification step decides whether the meaning it carries is true. An unverified explanatory image is worse than no image, because it teaches the audience something false with the full authority of a finished picture.

## Worked Example

Goal: generate an image that explains a three-stage data pipeline rather than decorates the slide.

1. Write a precise prompt that names the parts and their relationship:

   ```
   Flat diagram, three labeled boxes left to right:
   "Collect" -> "Clean" -> "Analyze", connected by arrows
   showing data flow. No people, no robots, white background.
   ```

2. Generate and inspect the result against the real process. First output reversed two stages:

   `Collect -> Analyze -> Clean`  (wrong: analysis cannot precede cleaning).

3. Revise the prompt to lock the order, then regenerate:

   `... in this exact order: Collect, then Clean, then Analyze ...`

4. Verify every label and arrow matches your actual steps before placing the image.

The reversed-order output is the teaching moment. The picture looked clean and professional and was still wrong, which is exactly how a generated diagram fails. Your critique log should record that you rejected the first output for transposing two stages, modified the prompt to fix it, and accepted the second only after checking every arrow against your real pipeline.

## Decision Rule

Decide whether the image explains or decorates, specify generated explanations precisely, and verify every element against reality before it goes on the slide. A polished image you did not check is a liability, not an asset.

Run a generated image through three questions before you use it:

1. **Purpose check:** Does this image carry information the audience needs, or is it decoration standing in for content?
2. **Evidence check:** Does every label, count, order, and arrow match your real process or data, and where did you confirm it?
3. **Revision check:** Which generated output did you reject or re-prompt, and what was wrong with it?

If you cannot point to where you verified the image, treat it as unverified and do not present it as an explanation.

## Common Misreadings

The first misreading is "the image looks professional, so it must be right." Visual polish and factual correctness are unrelated in generated images; the model optimizes for plausible appearance, not for matching your data.

The second is writing about the tool ("I used AI to make a diagram") instead of showing what you checked. The grade-worthy move is not that you generated an image; it is that you caught the reversed stages and fixed them.

## Textbook Walkthrough

Apply the two tests to a different content type: a generated icon set meant to label four product features. Specification first: rather than "icons for my app," you name each feature and the concept its icon must signal, so "upload" reads as an arrow into a tray, not a generic cloud. Verification second: you check that the four icons are visually distinct and that none accidentally implies the wrong feature, because a "download" arrow where you meant "upload" silently misleads.

Then weigh explanation against decoration. If the four icons help the audience tell the features apart at a glance, they carry meaning and stay. If they are just pretty thumbnails next to text that already names each feature, they are decoration competing for attention, and the honest move is to drop them. The same discipline that fixed the pipeline order applies here: specify, verify, and keep only what carries meaning.

## What Strong Reading Looks Like

As you read, keep a two-column note: on the left, each generated image you considered; on the right, whether it explains or decorates and what you verified. Flag any image you placed without checking its content. By the end of 05.03, your note should show a reviewer that no generated picture went on a slide unverified.

A strong reader of this section can answer four questions:

1. Does this image explain something the audience needs, or just decorate?
2. What exact parts and relationships did the prompt specify?
3. What in the output did you check against reality, and what failed?
4. Which output did you reject or re-prompt, and why?

## Stronger Artifact Standard

The critique log is strong when a reviewer can see, for each generated image, the prompt, the flaw you caught, the fix, and the final verification. Treat the polished final image as the least interesting part of the record. The decisions that matter are the rejection and the check.

A useful entry would sound like this: "I rejected the first pipeline diagram because it ordered the stages Collect, Analyze, Clean, which is impossible since cleaning precedes analysis. I re-prompted to lock the order and accepted the second only after confirming all three labels and both arrows matched my real steps. I rejected a third, flashier version with a glowing background because the glow carried no meaning and reduced contrast on the labels."

## Transfer Case

Suppose the assignment bans generated images entirely and you must explain the same pipeline with a built-in shape tool. The explain-or-decorate test and the verification habit transfer cleanly: you still draw three labeled boxes in the correct order, you still check the labels against your real steps, and you still drop any element that does not carry meaning. The tool changed; the reasoning that makes the image honest did not.
