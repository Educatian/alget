# AI Help for Excel Debugging

![AI Help for Excel Debugging textbook visual](/course-art/deep-exemplars/cat100-supplement/03-05-ai-help-for-excel-debugging.png)

An AI assistant can write an Excel formula faster than you can type it, but it cannot know whether the formula is right for your data. It does not see your sheet; it only sees the words in your prompt. So the value you get from AI debugging depends almost entirely on two things you control: how precisely you describe the problem, and how rigorously you verify the answer before you trust it.

This section treats AI as a fast assistant that is sometimes confidently wrong. The discipline it teaches is a loop: read the actual error code to diagnose the cause, write a prompt that names the exact cells and the behavior you want, then verify the returned formula on a row whose answer you already know. Skipping the diagnosis or the verification is how a plausible-looking AI formula ships a hidden bug.

## Opening Case

A cell in your gradebook shows `#DIV/0!` and you are stuck. You paste "fix my Excel error" into an AI chat and it returns a formula that uses functions you do not recognize, applied to cells it guessed at. You drop it in, the error disappears, and you move on, never noticing that the formula now reports the wrong average for half the class.

The error went away, but the bug did not. That is the danger of using AI without diagnosis and verification: it is very good at making errors disappear and only sometimes good at making them correct. The move this section builds is the opposite habit, reading what `#DIV/0!` actually means, telling the AI exactly which cells and which behavior, and checking its answer against a row you can compute yourself.

## Core Concept

Effective AI debugging rests on two skills: reading Excel's error codes and writing prompts that leave nothing to guess. Excel's errors are not random; each one names a category of cause, so the error code is your first diagnostic clue.

| Error | Means | Usual cause |
| --- | --- | --- |
| `#DIV/0!` | Division by zero | The denominator cell is blank or zero |
| `#REF!` | Invalid reference | A cell the formula pointed to was deleted |
| `#VALUE!` | Wrong data type | Text where a number is expected (`18 units`) |
| `#NAME?` | Unrecognized name | A misspelled function or undefined range name |
| `#N/A` | Value not found | A lookup found no match |

Reading the code tells you where to look before you ask anyone, human or AI, for help.

A good debugging prompt has four parts: the current formula, the error or wrong result it produces, the cause if you know it, and the exact behavior you want, including any edge case. Compare "fix my formula" with "My formula `=B4/D4` returns #DIV/0! because D4 is blank; I want it to show 'n/a' when D4 is empty and otherwise divide normally; give me one formula." The second prompt constrains the AI so tightly that its answer is easy to check. Then comes the non-negotiable step: verify the returned formula on a known-answer row, a row where you already know the correct result, before copying it anywhere.

## Worked Example

Suppose a class-average sheet shows an error in C4.

```
   A         B        C          D
1  Student   Points   Per Item   ItemCount
2  Maria     45       9.0        5
3  David     45       9.0        5
4  Sun       30       #DIV/0!    (blank)
```

The formula in column C is `=B2/D2` (Points divided by ItemCount). ItemCount lives in column D, which is blank for Sun's row, so Excel divides by zero and column C shows `#DIV/0!`.

Step 1. Read the error code, do not paper over it. `#DIV/0!` always means a divide-by-zero, so the denominator is the suspect, not the numerator.

Step 2. Write a precise prompt for the AI assistant: "My formula `=B4/D4` returns #DIV/0! because D4 is blank. I want it to show 'n/a' when D4 is empty and otherwise divide normally. Give me one formula."

Step 3. The AI returns `=IF(D4=0,"n/a",B4/D4)`. Do not trust it blindly. Verify on David's row, where D3 = 5 and B3 = 45 should give 9.0. The new formula returns `45/5 = 9.0`, which matches the value already there. Now it is verified, not assumed.

Step 4. Copy the verified formula down. C4 now reads `n/a` instead of an error.

## Decision Rule

Diagnose with the error code, prompt with exact cells and behavior, and verify on a known-answer row before you copy anything. An AI formula is a suggestion until you have proven it on a value you can compute yourself.

Run every AI fix through this gate:

1. **Diagnosis check:** Did you read the actual error code and form a guess at the cause before asking?
2. **Prompt check:** Does your prompt name the formula, the wrong result, and the exact behavior including edge cases?
3. **Verification check:** Did the AI formula produce the correct, already-known answer on a test row before you trusted it?

If you cannot point to a row where you confirmed the AI formula was right, you have not finished debugging.

## Common Misreadings

The biggest misreading is treating "the error disappeared" as proof the formula is correct. An AI fix that replaces `#DIV/0!` with a number can still compute the wrong number; the absence of a red error is not the presence of a right answer. Only a known-answer row settles it.

A second misreading is pasting a whole sheet of sensitive data into a chat to get help. The AI does not need the data to fix a formula; it needs the formula, the error, and the intended behavior. Describe the structure and share the formula, not the people's names, grades, or other private values.

## Textbook Walkthrough

Apply the loop to a lookup error in a price list. Column C uses `=VLOOKUP(B2, Prices, 2, FALSE)` to fetch a price for each product code in B, but a few rows show `#N/A`. The error code is your first clue: `#N/A` means the lookup found no match, so the suspect is the lookup value, not the table.

Diagnose before prompting. Inspect a failing row and you notice B7 reads `A-100 ` with a trailing space while the price table lists `A-100`; the space breaks the match. Now write a precise prompt: "My `=VLOOKUP(B2, Prices, 2, FALSE)` returns #N/A on rows where the code has a trailing space; I want it to match after trimming spaces; give me one formula." The AI returns `=VLOOKUP(TRIM(B2), Prices, 2, FALSE)`.

Verify before trusting. On a row you know is correct, where B3 is a clean `A-200` priced at \$15, the new formula must still return 15. It does, so the TRIM did not break the working rows. Now copy it down and the `#N/A` rows resolve.

## What Strong Reading Looks Like

A strong reader treats an AI formula the way a careful editor treats a draft: useful, but unverified until checked. The habits to build:

1. Read the error code first and predict the cause before opening a chat.
2. Notice when a prompt is too vague to produce a checkable answer, and tighten it.
3. Always identify a known-answer row to test the fix against.

When your instinct on receiving any AI formula is "let me test it on a row I can compute," you have internalized the safeguard that makes AI help trustworthy.

## Stronger Artifact Standard

A strong AI-debugging artifact shows the whole loop, not just the final formula. It records the original broken formula and its error code, the exact prompt you wrote, the formula the AI returned, and the known-answer row that confirmed it. A model line reads: "`=B4/D4` gave #DIV/0! on blank-denominator rows; I prompted for an n/a-on-empty version; the AI returned `=IF(D4=0,"n/a",B4/D4)`; I confirmed it returns 9.0 on David's row (45/5) before copying it down."

The weak version says "AI helped me fix the formula." The strong version lets a reviewer see what was wrong, what was asked, what was returned, and the proof it was right, so the AI's contribution is bounded and checkable rather than a black box.

## Transfer Case

The same diagnose-prompt-verify loop transfers from formulas to chart and pivot problems. Suppose a pivot total looks too low and you suspect the source range. You would not paste the workbook into a chat; you would describe the symptom ("my pivot of a 200-row log only totals about half the orders"), state your hypothesis ("I think the source range stops at row 100"), and ask how to confirm and extend the range. Then you verify by hand-counting a subset against the refreshed pivot. The tool changed from a formula to a pivot, but the discipline, name the symptom, hypothesize the cause, verify the fix, is identical, which is the sign you have learned the loop rather than one formula.
