# Formulas for Everyday Analysis

![Formulas for Everyday Analysis textbook visual](/course-art/deep-exemplars/cat100-supplement/03-02-formulas-for-everyday-analysis.png)

## Why This Section Matters

A formula is the difference between a spreadsheet that stores numbers and one that computes with them. The moment you write `=B3*C3` instead of typing the answer, the cell becomes live: change an input and the result updates, copy the formula down and it adapts to each row. That single shift, from typed values to referenced values, is the foundation of every analysis later in this module.

The skill that separates a working sheet from a broken one is understanding how references move when you copy a formula. Excel offers two behaviors, relative and absolute, and choosing the wrong one is the most common cause of a sheet that looks right at the top and goes silently wrong further down. This section teaches you to read a reference, predict how it will shift, and lock the parts that must stay fixed.

## Opening Case

You build an order sheet. In D3 you write `=B3*C3` for the first line total, it returns the right number, and you copy it down the column. Every line total looks correct. Then you add a shipping fee with `=D3+F1`, copy that down too, and the first row is fine but every row below it is wrong: the shipping silently drops to zero. You did not change the data. The formula moved in a way you did not intend.

This is the quiet trap of relative references. When you copy `=D3+F1` from row 3 to row 4, Excel rewrites it to `=D4+F2`, and F2 is empty. The fix is to know when to write `$F$1` so the reference stays put. Learning to see that shift before it bites is what this section is for.

## Core Concept

A cell reference like `B3` is an address, and a formula is a recipe written in terms of addresses rather than values. The key mechanic is what happens to those addresses when you copy the formula to another cell. Excel adjusts them by the same offset you moved.

There are two reference styles, and the dollar sign is the switch between them:

| Reference | Written as | When copied down one row | Use it for |
| --- | --- | --- | --- |
| Relative | `B3` | Becomes `B4` | A per-row input that should track each row |
| Absolute | `$B$3` | Stays `B3` | A single shared value (a tax rate, a fixed fee) |
| Mixed | `B$3` or `$B3` | Locks only the row or only the column | Filling a grid across both directions |

Read the dollar sign as a lock. `$F$1` means "lock the column F and the row 1, never move." A reference with no dollar signs is fully free and shifts in whatever direction you copy.

Beyond references, three functions cover most everyday analysis: `SUM(range)` adds a range, `AVERAGE(range)` means it, and `COUNT(range)` tallies the numeric cells. A useful warning: `AVERAGE` ignores blank cells but a stray zero is counted, so a blank and a zero give different averages. Knowing that distinction keeps your means honest.

## Worked Example

Suppose an order sheet looks like this. Quantity is in column B, unit price in column C, and the shipping fee for all rows is fixed in cell F1 = 5.

```
   A         B    C       D            E
1  Shipping  5
2  Item      Qty  Price   Line Total   With Ship
3  Mug       3    4.00     ?            ?
4  Pen       10   1.50     ?            ?
```

Step 1. In D3 write `=B3*C3`. That returns `3*4.00 = 12.00`. Copy D3 down to D4. Because B3 and C3 are relative, D4 becomes `=B4*C4 = 10*1.50 = 15.00`.

Step 2. In E3 write `=D3+$F$1`. The `$F$1` is absolute, so copying E3 down keeps pointing at the one shipping cell. E3 = `12.00 + 5 = 17.00` and E4 = `15.00 + 5 = 20.00`. If you had written `=D3+F1` instead, E4 would read `=D4+F2`, F2 is empty, and the shipping silently drops to 0.

Step 3. Total the orders with `=SUM(E3:E4)`, which returns `37.00`.

The decision a reader can audit: relative references (`B3`, `C3`) for per-row inputs, an absolute reference (`$F$1`) for the one shared fee. Mixing those up is the single most common formula error in this section.

## Decision Rule

Before you copy a formula, ask one question of every reference in it: should this address move with the fill, or stay fixed? Each input that belongs to the row stays relative; each value that is shared by all rows gets locked with dollar signs. Then test the bottom of the column, not just the top, because relative-reference errors hide below the first row.

Use this check on any column of copied formulas:

1. **Per-row inputs:** Are quantities, prices, and other row-specific values written as relative references so they track each row?
2. **Shared constants:** Is every value used by all rows (a fee, a rate, a target) locked with `$`, so the fill keeps pointing at the one cell?
3. **Bottom-row test:** Click the last filled cell and read its formula. Does it still reference the cells you intended, or did a relative reference drift onto a blank cell?

If the last row's formula points somewhere unexpected, you have a reference-locking error, not a data error.

## Common Misreadings

A frequent misreading is believing a formula is correct because the first result is correct. The first row often works by coincidence: `=D3+F1` is right in row 3 because F1 happens to hold the fee. The error only appears in row 4 when the reference slides to the empty F2. Always verify a copied formula at the bottom of its range.

A second misreading is confusing a typed answer with a computed one. If you type `12.00` into a line-total cell instead of `=B3*C3`, the number looks identical but will not update when the quantity changes. Reading the formula bar, not just the cell, tells you whether a value is live or frozen.

## Textbook Walkthrough

Apply the relative-versus-absolute decision to a study-budget sheet. Column B lists item costs, and cell E1 holds the sales-tax rate of 0.08. You want a "cost with tax" column.

In C2 you write `=B2*(1+$E$1)`. The `B2` is relative because each row has its own cost, and `$E$1` is absolute because every row uses the one tax rate. Copy C2 down: C3 becomes `=B3*(1+$E$1)`, exactly what you want, the cost reference advancing while the rate stays pinned. Had you written `=B2*(1+E1)`, the copy would become `=B3*(1+E2)`, and E2 is blank, so row 3's "tax" would vanish.

Verify at the bottom. Click the last filled cell, read the formula bar, and confirm the rate still says `$E$1`. Then total the column with `=SUM(C2:C20)` so a reader can re-add the line items and reach the same grand total.

## What Strong Reading Looks Like

A strong reader can look at a formula and narrate what it will become two rows down before pressing copy. Practice predicting the fill:

1. `=A2+B2` copied to row 3 becomes `=A3+B3` (both shift).
2. `=A2*$B$1` copied to row 3 becomes `=A3*$B$1` (only the free reference shifts).
3. `=A2/A$1` copied to row 3 becomes `=A3/A$1` (the locked row stays, the column would still shift if copied sideways).

When you can read a formula and forecast its copied form, you can debug a wrong column in seconds instead of retyping it.

## Stronger Artifact Standard

A strong formula artifact does not just show the final totals; it makes the reference logic legible. Label the shared constant clearly (a cell named "Tax rate" or "Shipping fee"), and in your trace note which cells are locked and why. A model line reads: "Shipping is fixed for all orders, so I locked it as `$F$1`; the per-row inputs B and C stay relative so each line total reflects its own quantity and price."

The weak version pastes a screenshot of right-looking numbers. The strong version lets a reviewer click any computed cell, read the formula, and confirm the lock pattern matches the logic you described. The proof lives in the formula bar, not the displayed value.

## Transfer Case

The same locking logic transfers to a multiplication grid, where you lock differently. Suppose row 1 holds prices across columns and column A holds quantities down the rows, and you want each interior cell to be quantity times price. The formula in the first interior cell is `=$A2*B$1`: the column of A is locked (`$A`) so the quantity always comes from column A, and the row of 1 is locked (`B$1`) so the price always comes from row 1. This mixed reference, locking one direction each, is the natural extension of the single-cell absolute reference, and recognizing when you need it shows you understand references rather than memorizing one pattern.
