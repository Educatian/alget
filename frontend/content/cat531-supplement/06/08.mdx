## Why This Section Matters

The capstone studio asks for something harder than four good artifacts; it asks for four artifacts that form one chain of judgment. A tension map that decides equity should govern, an implementation plan that quietly drops the equity fallback, a family memo that promises a safeguard the plan abandoned, and a reflection that never checks whether the safeguard worked, are four competent documents that contradict each other. Integration is the skill of making each artifact follow from the prior one, so that a reviewer reading the set sees a single coherent professional acting, not four assignments stapled together.

This is also where intellectual honesty gets tested under pressure. The temptation in a capstone is to smooth every artifact into a confident yes, resolving every tension and hiding every cost so the package looks finished. A stronger capstone keeps at least one hard tradeoff visible and shows how you reasoned through it, because the existence of an unresolved tension, handled openly, is more credible than a suspiciously frictionless story. The Design Tension Studio map is the keystone: its decision should be traceable into every other artifact in the set.

## Opening Case

A candidate submits the four Module 6 artifacts in order: tension map, implementation plan, family memo, evidence-based reflection, each on a pilot of an AI feedback tool. A reviewer reads them and writes one note: "These do not talk to each other." The map decided that equity should win, so the tool would be paired with a device fallback. But the implementation plan never schedules the fallback, the memo discloses a safeguard the plan does not actually deliver, and the reflection reports a class average that hides whether the fallback group kept pace. Each artifact is individually fine; together they describe a teacher who decided one thing and did another.

The failure is not in any single document but in the seams between them. A capstone is judged on coherence, and coherence lives precisely where one artifact must honor a commitment another artifact made.

## Core Concept

Integrating a capstone means building a traceable chain where each artifact discharges the obligations created by the previous one:

- **A decision that propagates.** The governing value chosen in the tension map (say, equity over efficiency) must visibly shape the plan, the memo, and the reflection. If equity won on paper but vanishes in the plan, the decision was never real.
- **Consistency across artifacts.** No later artifact may contradict an earlier commitment. A plan that drops the fallback the map required, or a memo that promises what the plan omits, breaks the chain and signals that the documents were written in isolation.
- **A preserved tradeoff.** Rather than resolving every tension into a clean yes, a strong capstone keeps one real, unresolved cost visible (the fallback consumes class time) and shows the reasoning that accepted it. Visible tradeoffs read as honesty; their absence reads as concealment.
- **A reflection that closes the loop.** The final reflection should test the very commitment the map made, with evidence, so the chain ends where it began rather than drifting to an unrelated conclusion.

This is synthesis applied to your own body of work: the same discipline that resolved competing values in Module 6 now must hold across four documents instead of within one. The course anchors audit the chain. TPACK checks that the through-line still serves a learning target; critical edtech studies checks that the equity commitment survives into the plan and reflection rather than being announced and abandoned; datafication checks that the memo's promises match what the tool actually does. A capstone where the artifacts agree only because each avoided the hard part is not integrated; it is merely uniform.

### Worked Example: An Annotated Capstone Integration Decision

Follow a teacher assembling the four Module 6 artifacts into one integrated final studio capstone.

1. **The four pieces.** Tension map (efficiency versus equity), implementation plan, family memo, and evidence-based reflection on a pilot of an AI feedback tool.
2. **Before (stapled).** First submission orders the four files but each was written on its own. A reviewer annotates: "These do not talk to each other."
3. **Trace the chain.** Revision makes the tension map's decision (equity wins, so keep a device fallback) drive the plan, which schedules the fallback, which the family memo discloses, which the reflection then tests with subgroup data.
4. **Fix the contradiction.** The reviewer flags that the plan had quietly dropped the fallback. The teacher restores it so a later artifact no longer contradicts the earlier value commitment.
5. **Keep a visible tradeoff (after).** Rather than smoothing every artifact to a confident yes, the capstone keeps one unresolved tension (the fallback costs class time) and shows how the teacher reasoned through it.

The before is a folder; the after is one chain of judgment where each artifact follows from the prior decision and the hard tradeoff stays visible.

## Decision Rule

Trace the keystone decision through every artifact before you polish any of them. The governing value from the tension map should be findable, by name, in the plan, the memo, and the reflection; wherever it disappears, you have a broken seam to repair. Coherence across artifacts outranks the finish of any single one.

Check the assembled capstone against three questions:

1. **Propagation check:** Does the tension map's governing decision visibly shape every other artifact?
2. **Consistency check:** Does any later artifact contradict an earlier commitment, such as a fallback promised then dropped?
3. **Honesty check:** Is at least one real tradeoff kept visible and reasoned through, rather than smoothed into a frictionless yes?

If any answer is missing, the capstone is a collection rather than an integration.

## Common Misreadings

The dominant error is the stapled portfolio: four artifacts written in isolation and ordered in a folder, which looks complete and falls apart the moment a reviewer reads across the seams. A related error is the silent contradiction, where a later artifact quietly abandons a commitment an earlier one made, usually because the teacher solved each document's local problem without rechecking the chain.

The subtlest and most costly misreading is over-smoothing. Believing a capstone should present total confidence, candidates resolve every tension and hide every cost, producing a package so frictionless that an experienced reviewer distrusts it. Real teaching involves accepted tradeoffs; a capstone that shows none has either avoided the hard decisions or concealed them, and either reading undercuts the very judgment the studio is meant to demonstrate.

## Textbook Walkthrough

A teacher's capstone centers on adopting an AI tutoring tool. The tension map decides that data privacy governs over convenience, so the tool will run only on school devices with a no-retention setting. Trace that keystone forward. The implementation plan must then schedule device access and verify the no-retention configuration as a gated prerequisite, not an afterthought; if the plan assumes home use to save class time, it has contradicted the map. The family memo must disclose exactly the no-retention practice the plan implements, with no promise the plan cannot keep. The reflection must then report whether the no-retention, school-only constraint actually held in practice and what it cost.

Now keep the tradeoff visible. The privacy decision costs flexibility: students cannot use the tutor at home, so some practice time is lost. A smoothed capstone would bury this; the integrated one states it, explains why privacy was judged worth the lost practice, and the reflection checks whether the lost practice hurt outcomes. A reviewer reading all four can follow one teacher's single decision from value to plan to disclosure to evidence, with the cost acknowledged throughout, which is exactly what an integrated professional vision looks like.

## What Strong Reading Looks Like

As you read a capstone, do not read the artifacts in isolation; read across them, tracking the keystone decision from the map into each later document and flagging every place it weakens, vanishes, or is contradicted. Then look for the tradeoff: a capstone with no visible cost has probably hidden one. By the end of CAT 531 06.08 you should be able to read any multi-artifact submission and locate its weakest seam, the point where one document fails to honor what another committed to.

A strong reader of an integrated capstone can answer four questions:

1. Is the tension map's governing decision traceable into every other artifact by name?
2. Where, if anywhere, does a later artifact contradict an earlier commitment?
3. What real tradeoff is kept visible, and is the reasoning that accepted it shown?
4. Does the final reflection test the original decision with evidence, closing the loop?

## Stronger Artifact Standard

A capstone is strong when a reviewer can trace one decision through all four artifacts without finding a broken seam, and when at least one honest tradeoff is visible and reasoned. Per-artifact polish is the last layer; the load-bearing layers are propagation, consistency, and visible honesty. If a seam breaks (a fallback promised then dropped), mark it and ask BigAL to compare the stapled version with the integrated version of that specific link rather than to "improve the capstone overall."

A useful closing line would read: "I restored the device fallback in the plan because my map decided equity governs, and a capstone that announces equity then drops its only safeguard is not integrated; I kept the class-time cost of the fallback visible because hiding the tradeoff would make the whole chain less trustworthy, not more."

## Transfer Case

Move the capstone discipline from this course to a school improvement proposal you might write as a practicing teacher: a problem statement, an action plan, a stakeholder communication, and an evaluation design. The artifacts differ, but the integration demand is identical: the value your problem statement commits to must propagate into the plan, survive into the communication, and be tested by the evaluation, with the real tradeoff kept visible. If you understood the capstone as a chain of judgment rather than a set of deliverables, you build coherent proposals for the rest of your career. If you only assembled four Module 6 files, the first real-world proposal with mismatched seams will read exactly as the stapled capstone did.
