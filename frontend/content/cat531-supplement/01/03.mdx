## Why This Section Matters

A Design Tension Studio map looks finished the moment it has boxes and arrows. That is exactly the trap. A map can be neat, color-coded, and completely unreadable as an argument, because the reader cannot tell from the picture how the values conflict or what was actually given up. Reading a map well is a separate skill from drawing one, and it is the skill a reviewer, a mentor, or a grade team will use to judge your reasoning.

This section matters because the same diagram supports very different decisions depending on how its parts are labeled. Two value nodes joined by an edge labeled "tension" assert that a conflict exists but explain nothing; a decision node that says "Use Tool X" hides whether anything was traded. Learning to audit nodes and edges turns a map from a decoration into evidence that another professional can inspect, question, and improve.

## Opening Case

A colleague hands you a tidy DTS map about adopting an automated essay scorer: two value nodes, one edge between them labeled "tension," and a decision node that reads "Use AutoScore." It looks complete. But you cannot answer the only questions that matter: how do the two values conflict, and what did the decision give up? The map asserts a conflict and a choice while hiding the mechanism of both.

Professional judgment becomes visible only when each part of the map is readable on its own. The opening task of this section is to learn what to interrogate, node by node, edge by edge.

## Core Concept

Reading a DTS map is an audit of three component types, each with a failure mode you learn to catch:

- **Value nodes** name what is at stake. Failure mode: a node that is actually a tool or a feeling ("AutoScore," "frustration") rather than a learning value. Fix: restate it as something you want for students ("fair feedback for multilingual writers").
- **Edges** name how two values conflict. Failure mode: a generic label like "tension" or "vs." that hides the mechanism. A readable edge names the causal link: "AutoScore is fast but was trained on native-speaker prose, so it penalizes multilingual sentence patterns." The edge is where most maps fail, because drawing a line is easy and explaining the conflict is hard.
- **Decision nodes** name the negotiated choice. Failure mode: a node that states a choice ("Use AutoScore") but hides the trade. A readable decision node states what was adopted, what was yielded, and why: "Use AutoScore for first-draft turnaround only; teacher re-scores flagged multilingual essays. Yielded: full automation."

The reading test is simple: every edge must name a mechanism, and every decision node must make a trade and its evidence visible. [TPACK](https://en.wikipedia.org/wiki/Technological_pedagogical_content_knowledge) helps you check that the value nodes are real learning values rather than tool names; critical edtech studies helps you check that the edge names a real cost rather than a vague worry. A map passes when a stranger can reconstruct the conflict and the trade without you explaining it.

## Worked Example

Scenario: you are reading the colleague's DTS map from the opening case. Reading a map well means auditing its nodes and edges, not admiring its layout. Walk it in four numbered moves.

**Before (the peer's map as drawn).**

> - Value node: "Faster feedback"
> - Value node: "Fair feedback for multilingual writers"
> - Edge between them, labeled: "tension"
> - Decision node: "Use AutoScore" (no trade-off note)

1. **Audit the value nodes.** Both are legitimate learning values. Keep both.
2. **Audit the edge.** The label is just "tension." That is unreadable. The reader cannot tell HOW the values conflict. Annotate it: "AutoScore returns scores in seconds (faster feedback) but trained on native-speaker prose, so it penalizes multilingual sentence patterns (fairness cost)."
3. **Audit the decision node.** "Use AutoScore" states a choice but hides what was yielded. A readable decision node reads: "Use AutoScore for first-draft turnaround only; teacher re-scores flagged multilingual essays by hand."
4. **Check evidence.** The decision node should cite what informed it: a 12-essay spot check showing AutoScore marked 4 of 5 multilingual essays a full band lower than the teacher did.

**After (the map made readable).**

> - Edge label: "AutoScore is fast but penalizes multilingual phrasing (12-essay check: 4/5 scored a band low)."
> - Decision node: "Adopt AutoScore for first-draft speed; teacher hand-re-scores any essay it flags below proficient. Yielded: full automation. Reason: speed gain does not justify systematic under-scoring of multilingual writers."

The map is now readable because every edge names a mechanism and the decision node makes the negotiation and its evidence inspectable, instead of asserting a choice with no visible trade.

**Recent evidence.** The 12-essay spot check above is a teacher's local, illustrative audit, but real research confirms the mechanism: GPT-based classifiers systematically misclassify non-native English prose (Liang et al., 2023, *Patterns*), because L2 writers use more constrained, less idiomatic phrasing the models were not trained to reward. Fairness audits therefore disaggregate error rates by subgroup rather than reporting a single accuracy number.

## Decision Rule

When auditing a map, read the value conflict first, the tool's affordance second, and the policy boundary third. A tool choice is justified only when it protects students while improving a specific learning activity, and the map must show that protection on its face.

Use this check when a map looks finished but the reasoning may still be hidden:

1. **Purpose check:** Are the value nodes real learning values, or are they tool names and feelings in disguise?
2. **Evidence check:** Does each edge name a mechanism, and does the decision node cite the observation that informed it?
3. **Revision check:** Does the decision node state what was yielded and why, or does it merely announce a choice?

If any edge says only "tension," the map is not yet readable.

## Common Misreadings

The frequent error is to write a general reflection about the map ("this was a hard trade-off") instead of repairing the unreadable parts of the map itself. Reflection is not a substitute for a legible edge. A second error is admiring layout: a beautifully arranged map with vague labels reads worse than an ugly one with precise labels. A third is accepting a decision node that names a winner without naming a loser; a trade with nothing yielded is not a negotiation, and a reader should distrust it.

## Textbook Walkthrough

Apply map-reading to a new artifact: a peer's DTS map about adopting an AI attendance-and-engagement camera that flags "disengaged" students. Read it as an auditor.

Audit the value nodes. One reads "engagement," the other reads "the camera." The second is a tool, not a value; restate it as the value it threatens: "student privacy and trust." Now both nodes are learning values that can genuinely conflict.

Audit the edge, which is labeled "balance." That hides the mechanism entirely. A readable edge names the causal cost: "the camera infers engagement from face and posture, which misreads neurodivergent and culturally varied expression, so it surveils students to chase an unreliable signal." Critical edtech studies supplies exactly this mechanism, and the affect-science evidence backs it: facial configurations do not reliably map to inner states across cultures, situations, and individuals (Barrett et al., 2019), and automated facial-expression classifiers that handle posed expressions adequately drop sharply on naturalistic ones (Kuntzler et al., 2021). Because the camera also collects face and posture data on minors, FERPA and COPPA set the statutory floor for the privacy side of the edge.

Audit the decision node, which says "Use camera in pilot." It announces a choice and yields nothing. Rewrite it so a reader sees the trade and its evidence: "Decline the camera; pilot a two-question exit ticket instead. Yielded: automated, continuous data. Reason: a 3-day trial flagged 5 attentive neurodivergent students as disengaged, so the signal is not trustworthy enough to justify constant surveillance." The walkthrough shows the same audit, applied to a different conflict, turning an opaque map into one a reviewer can act on.

## What Strong Reading Looks Like

As you read, keep a two-column note: each **map component** on the left, the **question it must answer to be readable** on the right. For a value node: is this a learning value or a tool name? For an edge: does it name a mechanism? For a decision node: does it name what was yielded? Mark every component that fails its question; those marks are your revision list.

A strong reader of DTS maps can answer four questions:

1. Are all value nodes genuine learning values rather than tools or feelings?
2. Does every edge explain the causal mechanism of the conflict?
3. Does the decision node state the trade and cite the evidence behind it?
4. Could a stranger reconstruct the negotiation from the map alone?

## Stronger Artifact Standard

The map is strong when a mentor can read it cold: value nodes are learning values, every edge names a mechanism, and the decision node states what was adopted, what was yielded, and the evidence behind it. The most common missing layer is the edge mechanism; if yours says only "tension," mark it and ask TeachGen@i to compare a generic edge label against a mechanism-naming one rather than for a general explanation.

A useful decision-node line sounds like: "Adopt for first-draft speed only; teacher hand-re-scores flagged essays. Yielded full automation, because the speed gain does not justify under-scoring multilingual writers (12-essay check: 4 of 5 a band low)."

## Transfer Case

Move the essay-scorer map into a class of confident, monolingual writers preparing for a timed standardized exam. The value nodes stay (fast feedback, fair feedback), but the edge mechanism weakens: if the scorer's training register matches the students, the fairness cost shrinks, and the decision node might legitimately read "adopt fully." If you cannot rewrite the edge and decision node for this new population, you were reading the map's picture rather than its argument.
