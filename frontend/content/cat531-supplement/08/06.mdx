# Low-Tech Fallbacks

![Low-Tech Fallbacks textbook visual](/course-art/deep-exemplars/cat531-supplement/08-06-low-tech-fallbacks.png)

## Why This Section Matters

A low-tech fallback is the part of a technology plan that decides what happens when the technology is not available. The AI tool will be down, a family will decline consent, a device will fail, and a network will drop. If the lesson only works when the tool works, then the tool has quietly become mandatory, and the students who cannot use it are simply left out. This section treats the fallback as a requirement of any defensible AI policy memo: a plan in which the AI tool is never the single point of failure for learning.

This matters because the learning target, not the tool, is what a teacher is accountable for. Persuasive writing is the target; the AI writing coach is one optional path to it. A policy memo that names an equivalent non-AI path keeps every student moving toward the target and answers, in advance, the privacy, consent, and equity objections a reviewer will raise.

## Opening Case

A policy memo states: "All students will use the AI writing coach for the persuasive essay unit." Then a family opts out, two students have no reliable device at home, and the vendor's terms turn out to permit retention of student text for training. The memo has no answer for any of these, because it assumed the tool always works and everyone consents. The students without a path are penalized by omission. The question this section answers is how to write the memo so that opting out, losing the device, or refusing consent never costs a student the learning.

## Core Concept

A defensible AI policy memo runs the proposed use through four checks and then names a fallback that survives all of them:

- **Privacy.** State what happens to student data. A memo should specify, for example, that the vendor contract bars retention of student text for model training. Silence on data is itself a finding.
- **Consent.** Assume some families will decline, and give those students a real path. A memo with no opt-out path makes the tool mandatory by omission.
- **Equity.** Identify who is disadvantaged by the logistics. Students without reliable home devices cannot use a tool assigned as homework, so any homework dependence becomes an access penalty. Keeping AI use in class on school devices removes that penalty.
- **Learning purpose plus fallback.** Tie the use to the actual target, then provide an equivalent non-AI path that reaches the same target. A printed peer-review protocol and a teacher conference can reach a persuasive-writing target without any tool.

The organizing idea is single-point-of-failure avoidance: a lesson should degrade gracefully when the technology is gone. The fallback is not a lesser version for "those kids"; it is an equivalent route that any student could take. Critical edtech studies supplies the habit of asking who is excluded when a tool is assumed, and TPACK keeps the fallback aimed at the same content goal rather than at a watered-down substitute.

## Decision Rule

When writing an AI policy memo, run the privacy and consent checks first, the equity-of-logistics check second, and the learning-purpose-plus-fallback check third. Before you treat the memo as finished, confirm it answers:

1. **Data check:** What happens to student data, stated explicitly rather than assumed?
2. **Access check:** What is the real path for a student who opts out or lacks a device, and does it reach the same target?
3. **Failure check:** If the tool is unavailable tomorrow, does the lesson still work for everyone?

A frequent error is treating the fallback as a courtesy rather than a requirement, something to improvise if a student complains. By then the exclusion has already happened. A second error is offering a fallback that reaches a lower target, which fixes the access problem on paper while creating a quality gap in practice; the fallback must be equivalent, not lesser. A third is treating privacy as a checkbox and not reading the vendor terms, which is where retention-for-training clauses usually hide.

## Textbook Walkthrough

Suppose you are writing the memo for an AI math-practice tool. Begin with data: does the vendor store student responses, and for how long? Write the answer in the memo. Then write the opt-out path and confirm it reaches the same skill, perhaps a printed problem set with the same targeted practice. Move the required use into class on school devices so no student is penalized at home. Finally, state the failure plan: if the platform is down, the printed set runs the lesson without interruption. That sentence is what makes the tool optional rather than load-bearing.

The artifact is the memo with explicit privacy and consent language, an equivalent opt-out path, in-class equity protection, and a named fallback that survives the tool being gone.

## What Strong Reading Looks Like

Read a policy memo by asking what breaks if the tool disappears. If the answer is "the lesson," the fallback is missing. Check that data handling is stated, not assumed, and that the opt-out path reaches the same target rather than a reduced one. Keep a two-column note: each of the four checks on the left, the memo sentence that satisfies it on the right. A strong memo has a sentence for every check and a fallback that any student could take without disadvantage.

## Stronger Artifact Standard

A policy memo meets the standard when a mentor teacher can see explicit data handling, a real consent path, in-class equity protection, and an equivalent fallback. Formatting is the last layer; the four checks and the fallback are load-bearing. If a check has no sentence, annotate the gap and ask BigAL to compare your memo against an exemplar that names a fallback rather than to make the language sound more official. A useful closing line reads: "I made the AI tool optional and named an equivalent low-tech path because the learning target cannot depend on the tool, and I rejected the all-students-must-use version because it excluded opted-out and no-device students by omission."

## Transfer Case

Move the memo to a tool used for a high-stakes summative assessment rather than for practice. The fallback requirement intensifies: if any student might be assessed without the tool, the non-AI path must be demonstrably equivalent in difficulty and standard, or the assessment is unfair. Rewriting the memo for the summative case, with attention to comparability of the two paths, rather than reusing the practice-tool version, shows you can scale the fallback principle to higher stakes.
