## Core Concept

The core idea in this section is that **Ethobot Transcript Annotation** should be treated as a relationship among purpose, constraint, evidence, and revision. Purpose names what the learner or audience needs to accomplish. Constraint names what limits the decision. Evidence names the source that makes the decision defensible. Revision shows what changed after the evidence was considered.

Three course anchors shape the reasoning here:

- **TPACK** helps you decide what counts as a meaningful learning or performance demand.

- **AI and education datafication** helps you check whether the artifact works for varied learners, audiences, or use contexts.

Use these anchors as lenses, not as names to drop into a reflection. A useful lens changes what you notice, what you question, and what you revise.

## Worked Example: Building and Applying an Annotation Code Scheme

Section 01 asked where reasoning shifted. This section is about the annotation method itself: a small, consistent code scheme a teacher can apply turn by turn so two readers would agree. Work it as numbered steps on the excerpt below.

Transcript excerpt (Ethobot 3.2, high-school AI-cheating debate):

1. Student: "Using AI to write is always cheating."
2. Ethobot: "Does it matter whether the teacher allowed it?"
3. Student: "If the teacher allowed it then it is not cheating, so the rule depends on the assignment."
4. Student: "But what about a student who cannot afford a tutor and uses AI instead?"

Step-by-step coding:

- Step 1. Define a 3-code scheme. CL = fixed claim, QU = a question that reframes, RE = reasoning that revises the prior position.
- Step 2. Apply codes per turn. Turn 1 = CL. Turn 2 = QU. Turn 3 = RE (revises the categorical claim). Turn 4 = RE (introduces an equity dimension).
- Step 3. Write the warrant beside each RE code. Turn 3 warrant = "now conditions cheating on teacher permission." Turn 4 warrant = "now weighs access and fairness."
- Step 4. Check inter-rater agreement. Ask whether a colleague applying the same scheme would code Turn 3 as RE. If the codes are subjective, tighten the definitions.

Before (weak): highlighting Turns 3 and 4 in yellow with the note "good thinking here."

After (strong): "Codes: T1 CL, T2 QU, T3 RE (warrant: cheating now conditioned on permission), T4 RE (warrant: equity of access introduced). Scheme is the CL/QU/RE rubric above so another rater can reproduce the coding. The QU at T2 is what triggered both RE turns."

The strong annotation uses a reusable code scheme with warrants, not subjective highlighting, so the judgment is reproducible.

## Decision Rule

Use the classroom value conflict first, the technology affordance second, and the policy boundary third. A tool choice is justified only when it protects students while improving a specific learning activity.

Before submitting the Ethobot transcript annotation showing where ethical reasoning changed, slow down and check whether the trace can answer three questions:

1. **Purpose check:** What should the audience be able to do after reading or using the artifact?
2. **Evidence check:** Which exact source, observation, annotation, rubric line, data pattern, or policy boundary justifies the revision?
3. **Revision check:** What changed in the artifact, and what suggestion did you reject or modify?

If you cannot answer all three questions, the artifact may be complete, but it is not yet ready as evidence of learning.

## Common Misreadings

A common mistake is to defend a technology because it is engaging. Engagement matters, but it does not replace evidence about learning, access, or risk.
